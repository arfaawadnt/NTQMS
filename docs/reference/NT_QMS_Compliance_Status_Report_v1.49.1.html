NT.QMS — Consolidated Compliance Status Report

A single status snapshot across every compliance stream: regulatory (21 CFR Part 11 / GAMP 5 CSV), quality-standard support (ISO/IEC 17025, ISO 15189, ISO 9001, GMP), enterprise architecture, and security. It consolidates the findings registers of all prior audits, states exactly what has been executed and by whom, and lists what remains — with owners. Every figure quoted was executed and observed, not estimated.

What this document is — and is not. This is an engineering compliance status report. It is not a regulatory approval, not a Computer System Validation (CSV) sign-off, and not a penetration-test attestation. Specifically:
  • The CSV re-validation (REVAL-NTQMS-001) is not signed. 18 OQ cases were executed, but on a development environment, by the engineering party, without independent witness signatures.
  • No independent penetration test has been performed. The security results here are from an in-house automated assessment against a development instance.
  • No staging or production runtime evidence exists (no deployed host was available): no TLS-at-proxy verification, no live alert firing, no 24-hour soak.
  • "Final" in the sense of this report means the end of the engineering work stream — it does not mean compliance is complete. Three conditions remain open (§7).
Claiming otherwise on the basis of this document would misrepresent the evidence.

9 · Lesson recorded — why the remaining conditions matter

A fully green test suite missed a real defect. Executing the OQ protocol by hand found OPS-010: on a cold start with PostgreSQL unreachable, the application crashed instead of starting and reporting /health/ready 503 — so a database outage coinciding with a restart became a crash-loop with nothing to interrogate. It had been invisible because every prior readiness test took the database down after startup, and the functional test host substitutes an in-memory database, so its "database down" cases only broke the health check. The defect is fixed, re-tested, and locked in by 6 regression tests.

This is the evidence-based argument for finishing SEC-001, DOC-001 and OPS-001 rather than treating automated green as sufficient assurance: the categories those conditions cover — adversarial testing by an independent party, witnessed execution on a qualified environment, and real runtime behaviour under load — are precisely the categories that hid this defect.
