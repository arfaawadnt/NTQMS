Modernizing the statistics cards — five options

Every tile below renders real numbers from your dashboard and the read.kpi_snapshot history (6 days), not placeholders. All five options fix the same set of defects in the current tiles (below) and use the existing brand tokens. Pick one and I'll apply it to the dashboard's 12 KPI tiles and the shared qams-list-stats component used across 28 module registers.

What's actually wrong today — measured, not opinion. The current tiles are solid saturated blocks with white text, one colour per metric. Running the palette validator over the seven tone tokens as a categorical set returns FAIL:
  • Red ↔ orange are ΔE 8.9 apart for normal vision (hard fail, floor is 15). "Overdue CAPA" (red) and "Open complaints" (orange) are genuinely hard to tell apart — and under deuteranopia they collapse further (ΔE 8.2).
  • Contrast below 3:1 vs the surface for teal (2.58) and gold (1.80) — which is why gold already needs dark text hard-coded to stay legible.
  • Gold is too light and slate too dark for one band, and slate is below the chroma floor (it reads grey).
  • Colour is doing the work alone — no icon, no label, no shape carries severity, and the hue means "this module" in one place and "this severity" in another.
  • The big value uses tabular-nums, which makes display-size numbers look loose.
Every option below therefore moves colour off the block and onto an accent, puts values and labels in text ink, and pairs severity with a second channel (position, icon, or dot).
