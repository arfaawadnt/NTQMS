6 · Executive summary

NT.QMS is a mature, well-architected multi-tenant SaaS QMS whose highest-risk controls are implemented and proven by executed automated tests. Clean Architecture and module boundaries are enforced as merge gates (LayerRulesTests, ModuleBoundaryTests); the domain is framework-free; CQRS is real (separate commands/queries, a tested behaviour pipeline, DTO projection, no leaked IQueryable); tenant isolation is enforced at both the EF query filter and PostgreSQL FORCE RLS and validated against a real database, including a live cross-tenant IDOR probe that returned 404; authorization is deny-by-default at both the HTTP fallback policy and the command pipeline, proven by a 6-role × endpoint matrix; the audit trail is hash-chained with executed tamper-detection; e-signatures bind the full Part-11 evidence set; the session model uses a rotating, reuse-detecting refresh cookie (ADR-0009). The database is normalized with FK/unique/CHECK constraints, tenant-scoped uniqueness, optimistic concurrency (xmin), and reversible migrations. The outbox is durable, retry-safe, dead-lettering, and horizontally safe (SKIP LOCKED + leader election).

The material gaps are operational and external, not architectural: no independent penetration test; no staging run of the (authored) observability stack, load, or soak; no dependency/container vulnerability scanning in CI; and currency deviations (Angular 18 vs 19; MS-JSON+OTel vs Serilog by name). Several validation (OQ/PQ) cases remain QA-execution templates. None of these are cross-tenant, authorization, data-corruption, or secret-exposure defects — so none is a P0 blocker. The system is approved with conditions.

13 · Aggregate & domain-model assessment
