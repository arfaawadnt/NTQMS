NT.QMS — Enterprise Architecture Compliance Audit
Current State (v1.49.1)

Fourth re-audit, superseding EA-AUD-NTQMS-003 (v1.48.0). It covers what changed after the engineering ceiling was reached: CI supply-chain scanning, the Angular 18→22 security upgrade, a witnessed execution of the validation protocol — and the real defect that execution uncovered (OPS-010), now fixed. Same evidence-based method: every score is backed by an executed build, the automated suite against real PostgreSQL 17, the frontend + e2e gates, live drills, and the green CI pipeline.

Verdict — Compliant · engineering ceiling held, supply chain now clean

Overall compliance ≈ 98% (unchanged) — the remaining ~2% is still external-only

Three items closed since v1.48: dependency/container scanning is in CI, the SPA runs Angular 22.0.8 with zero known advisories in shipped dependencies (it previously carried 10 high-severity framework advisories that no one had detected), and OPS-010 — a cold-start crash when PostgreSQL is unreachable — was found by executing the OQ protocol and fixed. The score is deliberately unchanged: the external remainder (penetration test, formal CSV re-validation on a qualified environment, staging telemetry/soak) is exactly what it was. Closing engineering gaps that were previously scored as met does not buy percentage points.

Correction to EA-AUD-NTQMS-003 (v1.48). That report scored Observability & operational at 96 and stated that readiness returns 503 "when the database is down". Executing the protocol showed that was true only for a database that fails after startup: on a cold start with PostgreSQL unreachable the process crashed before it could serve /health/ready at all. Every prior readiness test — automated and drill — had taken the database down after startup, so the gap was invisible. The v1.48 score therefore rested partly on an untested claim. The defect (OPS-010) is now fixed and re-tested; the score stays 96 because the staging soak remains open, not because the correction was cost-free.
