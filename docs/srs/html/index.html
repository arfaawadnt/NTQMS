NT.QMS — As-Built Software Requirements Specification

This is the as-built specification of NT.QMS — reverse-specified from the source tree at release line v1.51.x. It documents the system that exists: every module, rule, validation, error path, configuration key, screen, workflow and constraint found in the code. It supersedes NT_QMS_SRS.html, which describes a materially different system.

Evidence convention. Statements without a marker are verified in source. Anything inferred is marked [Assumption]; behaviour whose business intent is undocumented is marked [Needs Business Confirmation]; capability never observed running in this environment is marked [Not Executed]; unreachable code is marked [Dead / Unused].

Reading order for a rebuild team

  1. Doc 01 — scope, actors, constraints.
  2. Doc 11 — the architectural law, before designing anything.
  3. Doc 06 + Doc 03 — the state machines and rules are the product.
  4. Doc 02 — module by module; the dependency notes give a build order.
  5. Doc 08 + Doc 05 — surface contracts, API first then screens.
  6. Doc 04 + Doc 07 + Doc 10 — make it run.
  7. Doc 09 — security is not a phase; read it before, during and after.
  8. Docs 12–15 — verify what you built, and inherit the debt list knowingly.
