3. Document Target & Purpose

This Software Requirements Specification (SRS) defines the mandatory functional, compliance, security, and technical requirements for the NT.QMS Quality Management System. It serves as the authoritative, contractually binding baseline for development, validation (IQ/OQ/PQ), and regulatory audit compliance.

What vs. How Rule: This document strictly specifies WHAT NT.QMS must perform and enforce. Technical design blueprints (ADRs) dictate internal code architecture, provided they fulfill every requirement defined herein without deviation.

4. Executive Summary

NT.QMS is an enterprise, multi-tenant Quality Management System designed to digitize laboratory and manufacturing operations under ISO 9001, ISO/IEC 17025, and 21 CFR Part 11. It resolves legacy paper-based friction, un-tracked approvals, and audit vulnerabilities by delivering 40 core registers, automated SLA escalations, hash-chained tamper-evident audit trails, and page-level PDF/Excel data export engines.

10. Functional Modules Requirements Specification

This section details the 30 core functional modules of NT.QMS. Every module enforces strict data validation, business rules, permissions, audit trails, and export capabilities.

MOD-03: IAM & TENANT SECURITY 21 CFR Part 11 Mandatory
Identity, Multi-Tenancy (RLS), TOTP MFA & E-Signature PIN

Overview: Manages authentication, multi-tenant isolation via PostgreSQL Row-Level Security (RLS), TOTP MFA enrollment, and 4-digit E-Signature PIN registration.

Functional Requirements

  • IAM-FR-001 (RLS Isolation): Every database query executed by qams_app MUST evaluate current_setting('app.current_tenant'). Direct cross-tenant access attempts MUST return HTTP 401/403.
  • IAM-FR-002 (TOTP MFA Gate): Account logins MUST enforce 6-digit TOTP validation when MFA is enabled. 5 failed login attempts trigger an automatic 30-minute lockout.
  • IAM-FR-003 (E-Signature PIN): The system MUST maintain a salted hash of a 4-digit user PIN used exclusively for Part 11 signature ceremonies. The actual PIN value MUST NEVER be stored or logged.

Business Rules & Permissions

IAM-BR-001 (Deny-by-Default): All API endpoints require JWT Bearer authorization except /api/auth/login and /health/*.
MOD-05: DOCUMENT & SOP CONTROL ISO 9001 §7.5 / 17025 §8.3
Controlled SOP Lifecycle, Versioning & Segregation of Duties

Overview: Controls document authoring (Draft → Review → Approval → Published → Obsolete). Enforces strict Segregation of Duties (Author ≠ Approver).

Functional Requirements

  • DOC-FR-001 (Versioning): Major updates increment integer version (v1.0 → v2.0); minor edits increment decimal (v1.0 → v1.1). Publishing v2.0 automatically marks v1.0 as Superseded.
  • DOC-FR-002 (Part 11 Signing Ceremony): Publishing a document requires the Approver's 4-digit PIN + password re-authentication, writing an immutable record to qams.signature_record with SHA-256 content hash.
  • DOC-FR-003 (Controlled Copies): Downloaded PDFs MUST feature dynamic watermarking ("CONTROLLED COPY - Printed by {User} on {Date}").
MOD-08: NONCONFORMANCE (NC) ISO 17025 §7.10
Race-Free NC Reference Numbering, Containment & RCA

Overview: Captures quality deviations across 9 states (Raise → Submit → Triage → RCA → CAPA Link → Verification → Closed). Guarantees race-free NC-YYYY-NNNN numbering.

Functional Requirements

  • NC-FR-001 (Atomic Numbering): NC identifiers MUST be generated atomically via database sequence, preventing duplicate numbers under concurrent requests.
  • NC-FR-002 (Auto-NC Link): An unsatisfactory Proficiency Test (PT) result or audit finding graded as "Nonconformity" MUST automatically raise an NC record (idempotent cross-module saga).
MOD-10: CAPA MANAGEMENT ISO 9001 §10.2
Action Plans, SLA Ladder Escalations & Effectiveness Check

Overview: Manages Corrective and Preventive Actions with SLA escalation timers (+24h Owner / +48h Dept Mgr / +72h Quality Director).

Functional Requirements

  • CAPA-FR-001 (SLA Timers): Planning a CAPA action arms an escalation timer. Overdue actions advance through escalation steps, generating My-Tasks work items and notifications.
  • CAPA-FR-002 (Effectiveness Gate): A CAPA record CANNOT be closed without a mandatory effectiveness verification evaluation after a configured cooling period (e.g. 30 days).
MOD-16: EQUIPMENT & CALIBRATION ISO 17025 §6.4
Instrument Registry, Auto-Lockout Sweep & Service Certificates

Overview: Manages equipment lifecycle, calibration schedules, and automated out-of-service lockout state machines.

Functional Requirements

  • EQP-FR-001 (Hourly Lockout Sweep): An hourly background job evaluates equipment calibration expiry. Expired instruments transition to GracePeriod or OutOfService, locking analytical testing.
MOD-27: AUDIT TRAIL LEDGER 21 CFR Part 11 §11.10(e)
Hash-Chained Append-Only Ledger & Tamper Verification

Overview: Records every system domain event into a cryptographic hash-chain (SHA-256). Provides on-demand verification of ledger integrity.

Functional Requirements

  • AUD-FR-001 (Hash Chaining): Each entry stores EntryHash = SHA256(PrevHash + EventPayload + OccurredAt). Database triggers block UPDATE and DELETE operations on audit records.

18. 21 CFR Part 11 Compliance Specification

FDA 21 CFR Part 11 Mandates Supported

  • §11.10(b) Inspection Manifest: On-demand PDF/Excel exports containing clear provenance timestamps and user identity.
  • §11.10(e) Audit Trail: Computer-generated, time-stamped, hash-chained audit trails tracking operator actions without overwriting prior data.
  • §11.50 Manifestation of Signatures: Printed name, date/time UTC, and explicit meaning (e.g. "Approved as Authoritative SOP") attached to signed records.
  • §11.70 Signature Linkage: Digital signatures bound cryptographically to their respective document content via SHA-256 hash.
  • §11.300 Password/PIN Controls: 4-digit E-Signature PIN requiring dual-factor validation for signing ceremonies.
